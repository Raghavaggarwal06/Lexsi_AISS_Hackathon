Tiny Aya can tell dangerous requests from ones that only sound dangerous

We looked inside the model right before it answers. By layer 23, dangerous prompts and harmless prompts sit in different places, even when they are written the same way.

GO

A strictness knob has something real to read from, so Phase 2 can start. Phase 1 only shows that the model detects the difference. It does not show that the knob works.

What you are looking at

Inside the model, each prompt becomes a list of 2,048 numbers at each of its 36 layers. You can't look at that directly, so we compress it into pictures. Each dot is one prompt. Its color tells you what kind of prompt it is. Its position shows how the model represents it. These are prompts only. The model has not written any answers yet; that happens in Phase 2.

When the model figures it out

Each row is a kind of prompt and each column is a layer. Stronger color means more of those prompts were flagged. The top two rows should be strong and the bottom three faint. The mistakes at layer 23 are understandable

These harmless prompts crossed the line. Most touch sensitive topics such as drugs, fake IDs or sexual content, so it is reasonable that the model sees them as close to the edge. OR-Bench is the weak spot: about one in three of those prompts is flagged. The score next to each prompt uses the same scale as above.

Why the first layer choice was wrong

Our GO rule needs a high score on harmful vs xstest_safe and harmful vs orbench_hard. But those groups come from different datasets, with different writing styles. A simple word counter (TF-IDF), which never touches the model, nearly solves both.

The fair test is prompts written the same way: xstest_unsafe against xstest_safe. That is the row the word counter cannot solve.

The first run picked layer 11 and said GO, but that layer was mostly reading style. We then added the same-format test to the layer choice, using only the half of the data held for fitting, and it moved to layer 23. We changed this after seeing the first result, so the write-up has to say so. The GO thresholds themselves did not change.

What this proves, and what it does not

Shown by Phase 1

  • At layer 23 there is a signal that separates real danger from apparent danger.
  • It holds on prompts that were not used to compute it.
  • Candidates A and B stay alive, so candidate C is not needed yet.

Still unknown

  • Whether pushing the model along this direction makes it refuse more. Detecting is not controlling.
  • Whether the knob is selective: Phase 2 needs at least 8 points fewer refusals on harmless prompts than the control.
  • Whether it survives being folded into the weights, which is Phase 3.

The decision for Phase 2

Layer 23 has two versions of the danger direction. Raw is the plain difference between dangerous and benign averages. Cleaned also removes the 5 biggest patterns in benign prompts. Every picture above uses raw.

Recommendation: use raw. It separates same-format prompts better and raises far fewer false alarms on XSTest. The cost is about 5 points more false alarms on OR-Bench. This reads the held-out half, so treat it as a judgment call and not a clean selection.

How this was made. The map is PCA fitted on the fit half with no labels, then applied to the held-out half shown here. PCA was chosen over UMAP or t-SNE because those tools distort distances and rearrange the picture from one layer to the next, which would make layer comparisons misleading. The map keeps only part of the variation, as noted above it; the score and the AUROC use all 2,048 numbers. Reading a concept as a direction follows the same approach as Arditi et al. 2024 (arXiv:2406.11717).

Details. "Layer k" is the output of decoder layer k-1. The flag line is set to catch 90% of the fit-half dangerous prompts. Held-out sizes: 146 harmful, 100 xstest_unsafe, 125 orbench_hard, 125 xstest_safe, 125 benign. Text of dangerous prompts is withheld from this page.
